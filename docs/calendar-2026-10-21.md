# Note calendar — 2026-10-21 KST

This historical layout and verification record is superseded by [the calendar list update](followup-2026-10-21.md). Dates now show previews and no longer open or arrange all notes.

## Behavior

- A calendar button sits immediately after New note in each note toolbar.
- The calendar opens in its own window, in a free part of the monitor work area.
  Existing visible notes and settings windows are treated as obstacles.
- The default content size is 560 × 420 logical pixels, with a 520 × 420 fallback
  when a narrower free area is available. There is no clock or bottom status text.
- Each date shows its surviving note count in red, for example a localized label
  meaning "3 notes created".
  Dates follow the PC's local time zone. Deleted notes and the synthetic welcome
  timestamp are excluded. Counts refresh while the window is open.
- Clicking a date opens its notes, including hidden or minimized notes, in creation
  order. Placement avoids the calendar, unrelated visible windows and other selected
  notes. Only selected notes may shrink when necessary to fit. If even their minimum
  size cannot fit, an error is shown before the layout is changed.
- Window bounds include Windows' invisible resize borders, and placement uses physical
  coordinates to avoid mixing monitor DPI scales. Positions and sizes stay device-local.
- New notes use the actual PC timestamp even when a synced note has a future timestamp
  or the Windows clock has been moved back. Existing note timestamps are preserved.

## Integration and concurrent work

Calendar UI, messages and IPC are isolated under `src/lib/calendar/`; Rust commands,
placement and geometry tests are in `src-tauri/src/calendar.rs`. Integration changes
are limited to `App.svelte`, the note toolbar, command registration and the calendar
window capability. The timestamp correction and regression test are in `store.rs`.
Existing font, MCP and storage changes were retained. No dependencies were added.

Calendar changes are included in the [current release](verification-2026-10-21.md).

## Observed validation

- `npm run check`: zero errors and warnings.
- Vite production build: passed; existing chunk-size warning remains.
- Rust suite: 39 tests passed, including packing, invisible frame extents at 150% DPI,
  negative monitor coordinates, day boundaries and future timestamp regression.
- `node scripts/test-calendar-dates.mjs`: passed for KST, time zone changes,
  23/25-hour DST days, month boundaries and leap years.
- Native WebView2, Windows at 150% DPI: the compact calendar rendered at 560 × 420
  logical / 840 × 630 captured pixels in Korean and English. Red count labels fit;
  the clock and bottom status area were absent.
- Native geometry inspection: the calendar and six visible notes had no intersecting
  outer rectangles after opening consecutive dates. Hidden notes were restored.
- Creating a note in a collection containing tomorrow's notes produced a timestamp
  between the actual PC timestamps taken before and after creation. Live counts
  increased on creation and decreased on deletion. Choosing an empty date created
  no windows.
- Changed source files were verified as valid UTF-8 without BOM and LF.

Intermediate UI captures have been removed. Retained evidence for the delivered
build is linked from the [current release record](verification-2026-10-21.md).

Multiple monitors with different physical DPI settings were not exercised on hardware;
coordinate handling was inspected and geometry edge cases were covered by unit tests.
