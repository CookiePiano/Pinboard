# Pinboard feature update — 2026-10-21 KST

This earlier release is superseded by [the calendar and explicit MCP setup update](followup-2026-10-21.md). Its selection-tool toggles, task checkboxes and calendar behavior describe the earlier build.

The update adds screen-edge and note-edge snapping, temporary foreground elevation for focused notes, per-note photo backgrounds, selection formatting, theme selection, and disabled states for optional features. The existing language hint was removed. The note creation, store, restore, calendar and MCP paths have no application-defined note-count limit.

## Behavior

- Windows notes snap within 14 logical pixels of work-area edges and visible note edges. The native move loop uses physical coordinates, per-window DPI, monitor work areas and DWM visible bounds to account for invisible resize borders. Dragging beyond the threshold detaches a note. The calendar is excluded from note snapping registration.
- Every focused note becomes topmost. Blur restores Normal, Always on top or Desktop without changing the saved mode.
- Design sits above Sync. Opening settings from a note selects that note as the design target. Photos are centered with `object-fit: cover`, resized to at most 2560 pixels on the longer side, encoded locally as WebP and stored in the note JSON. Photo transparency is independent of the note tint. Images and formatting participate in sync content hashes; absent fields retain legacy hashes.
- Text selection shows B, I, minus, plus and H. Sizes use points, with a default step of 1pt. Mixed title/body sizes retain their relative difference. Formatting ranges use UTF-16 offsets, follow edits, and support undo/redo. General settings control the toolbar, individual tools, size step and highlighter color.
- System, Light and Dark modes apply across note, settings and calendar windows. System mode follows OS changes. Dark mode retains six distinguishable note tints.
- Disabled shortcuts and MCP settings are dimmed and their dependent controls are disabled.

## Validation

- Svelte/TypeScript: zero errors and warnings.
- Rust: 43 tests passed, including snapping on negative monitor coordinates, work-area boundaries, detachment, legacy settings and note compatibility, and appearance hashes/round trips.
- `node scripts/test-formatting.mjs`: mixed styles, partial toggles, sizes, size bounds, Unicode positions, insertion/deletion mapping and mixed title/body size increments.
- `node scripts/test-calendar-dates.mjs`: calendar regression checks passed.
- Production frontend, native executable, NSIS installer and standalone removal wizard built successfully. Vite retains the existing chunk-size advisory.

Native verification used isolated data and WebView2 profiles under `C:\build\pinboard-features-20261021`, with agent-browser attached only to the test app. At 760 × 540 CSS pixels, the inherited settings layout was inspected against the original UI. The note was also inspected at 280 × 260 and an emulated minimum viewport of 180 × 120 CSS pixels. This is scoped refinement, not a pixel-matching claim against a generated design.

The verified paths include light/dark switching; disabled shortcut/MCP controls; image upload, note targeting, cover rendering and transparency; bold, italic, 1pt enlargement, highlighting and changed highlight color; formatting undo/redo; and persisted data after restart. Windows read-only window inspection confirmed focus/blur topmost states in all three pin modes, including restoration of Desktop to the bottom of the app's window order.

The Computer Use window list excludes the note tool windows, so a physical mouse drag through the Windows move loop was not automated. Snapping geometry is covered by Rust tests; manual multi-monitor dragging and a Linux runtime remain unverified.

The original user process and data were preserved. Task-created browser sessions and native test instances were closed. Current artifact hashes are recorded in [the feature artifact receipt](verification/feature-release-artifacts.json).
